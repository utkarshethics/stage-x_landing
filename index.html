Where FDEs Deliver Frontier AI

Frontier AI doesn't fail on raw reasoning capability—it fails at the integration boundary with air-gapped VPCs, legacy SCADA/ERP protocols, and dirty telemetry. Here is where Forward Deployed Engineers (FDEs) write code, optimize kernels, and ship frontier models directly inside enterprise infrastructure.

Field Mission 01 U.S. Air Force • F-35 Joint Program Office

Air-Gapped Fleet Readiness & Predictive Depot Supply

  • vLLM / FP8
  • Local GGUF / Air-Gapped
  • Zero-Egress PrivateLink
  • OPC-UA Bridge

Situation

Aircraft maintenance depots lost weeks per turnaround. Technical orders spanned 40 years across three incompatible document systems, maintenance logs were hand-keyed from paper, and the whole facility sat behind an air gap that made every off-the-shelf retrieval product unusable.

Bottleneck

Retrieval, not inference. A technician with the correct answer in hand still lost 30 to 70 minutes to search, because the bottleneck was a lexical index over scanned PDFs with no semantic layer and no way to reach a hosted vector store from inside the SCIF.

Architectural Fix

Everything moved inside the perimeter. Weights quantized to FP8 GGUF and served by a local vLLM instance, a hybrid BM25 plus HNSW index built on the depot's own storage, and an egress policy pinned to drop_all at the kernel rather than at the application layer. Retrieval moved from 70 minutes to under 4.

THE WORKFLOW

Four phases, run as an engineering runbook rather than a consulting engagement. Each one ends with something running in the client's own environment.

RECON

Enumerate every hop between the historian and the systems of record. Wire-level packet capture on the plant floor, a container vulnerability scan of the target runtime (Trivy against the exact image digest), and one working path through the oldest protocol in the stack before a line of new code is written.

Exit criterion: one reproducible failure

FUSION

Write the connector, not the wrapper. Native BAPI/RFC and OPC-UA v1.04 adapters, Kafka and gRPC fan-in, weights and runtime moved into the client's private repository. No vendor artifact is ever left in the data path, and nothing is phoned home to be licensed at run time.

Exit criterion: repo owned by the client

HARDENING

Break it before it breaks production. A red-team fuzz harness is run against the parser and the retrieval index, egress is pinned to drop_all at the kernel rather than the application, and a rollback drill is rehearsed against the live topology with the client's on-call in the room.

Exit criterion: signed artifacts + SBOM

TRAINING

Leave the pager with them. Paired on-call until the client's own operators hold the runbook, the dashboards and the incident channel. The handover, not a dashboard, is the deliverable; support recedes once they run a shift without us.

Exit criterion: client runs the shift

[ENV-REF: TIER-1 POWER GRID HARMONIC DRIFT] SEV-2 · RESOLVED

Root Cause Analysis & Deployment Cutover

Harmonic distortion on the 138kV feeder peaked during the overnight EV charging window. Two prior vendors had routed inference to a hosted endpoint, which the utility's compliance boundary forbids, so every attempt stalled at the network review. We bypassed that boundary entirely: the inference gateway was moved onto a PrivateLink endpoint inside the client's own VPC, and the egress rule was set to drop_all at the security group rather than relying on application-level filtering. The cutover happened at 02:14 local during the scheduled feeder outage window, with the balancing loop running in shadow mode for 40 minutes against live state-estimation output before we let it write.

Telemetry validation was handed to the client's own grid operations team rather than left with us. They replayed eighteen months of AMI history through the deployed model and signed off on the residual error band themselves. The runbook, the dashboards and the rollback switch were moved into their repository at handover; our access was revoked on their schedule, not ours.

[ENV-REF: DEPOT TURNOVER QUEUE SATURATION] SEV-3 · RESOLVED

Retrieval Latency & Read-Hostile Document Corpus

The depot was not compute-bound, it was retrieval-bound. Forty years of technical orders had been OCR'd into scanned PDFs with no semantic layer, so a technician with the correct answer in hand still lost up to 70 minutes to search. The exact network failure that had blocked every previous attempt was not bandwidth but architecture: an air-gapped facility has no route to a hosted vector store, and polling a historian over HTTPS at that corpus size never completed a full index build inside a maintenance window.

We quantized weights to FP8 GGUF, served them from a local vLLM instance, and built a hybrid BM25 plus HNSW index on the depot's own storage, then pinned egress to drop_all at the kernel so the constraint was enforced below the application. Median part-requisition resolution dropped below four minutes. The retrieval index, the weights and the query harness now live in the depot's own repository; the client's maintainers ran the last three index rebuilds unsupervised and we were paged zero times.

[ENV-REF: PLANT EDGE CONTROL LOOP INTERLOCK] SEV-2 · RESOLVED

Real-Time Control Integration & Safety Interlock Handover

The kiln runs at 1,400°C and cannot be paused to accommodate an untested control path. Rather than proposing values to the PLC, the model reads a read-only OPC-UA subscription and proposes; the existing interlocks decide. Cutover happened at 02:40 during a scheduled refractory inspection window, with every proposal shadowed against the plant's own lab tolerance checks before the write path was opened. The network failure that had stalled earlier attempts was the vendor's assumption of bidirectional plant connectivity, which the process network does not permit.

Telemetry validation and rollback both belong to the client's process engineers now. They hold the interlock, the shadow-mode switch and the runbook; our role ended when they walked us out of the control room and kept the model live. Fuel burn and unplanned downtime are measured on their historian, not ours.

Initializing the runtime

This is the whole integration. Declare the enclave, pin egress, open the audit stream, bridge the protocol.

Quick install: pip install stagex-runtime Repo: github.com/stage-x/runtime
harness.py 
from stage_x import Runtime, AirGapEnclave

harness = Runtime(
    enclave=AirGapEnclave.from_env(),
    egress_policy="drop_all",
    audit_stream="syslog:///var/log/stagex.audit",
)

harness.bridge(
    protocol="opc-ua",
    endpoint="opc.tcp://10.20.0.12:4840",
    write_mode="propose_only",
)

harness.index(corpus="./technical-orders", mode="hybrid")
package main

import "github.com/stage-x/runtime"

func main() {
    rt := runtime.New(runtime.AirGapEnclave, runtime.PolicyDropAll)
    rt.BridgeOPCUA("opc.tcp://10.20.0.12:4840", runtime.ModeProposeOnly)
    rt.ServeHybridIndex("./technical-orders")
}
